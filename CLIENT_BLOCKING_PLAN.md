# Блокировка клиента мастером

## Цель

Мастер может заблокировать конкретного MAX-клиента. Блокировка действует только
для пары `masterId + clientId`: тот же клиент продолжает пользоваться услугами
других мастеров.

Заблокированный клиент:

- не может открыть профиль этого мастера в клиентском miniapp;
- не может самостоятельно создать или перенести запись к этому мастеру;
- не получает клиентские уведомления от этого мастера;
- продолжает видеть мастера в списке последних мастеров.

Мастер по-прежнему может создать запись клиенту вручную. Существующие записи не
отменяются. Удаление клиента пока остаётся без дополнительной взаимосвязи с
блокировкой: удаление строки `MasterClient` удаляет и её состояние блокировки.

## Данные и API

Источник истины находится в backend-репозитории `../max-bot`.

1. Добавить `MasterClient.blockedAt DateTime?` и Prisma-миграцию.
2. Возвращать `isBlocked` и `blockedAt` в DTO адресной книги мастера.
3. Добавить идемпотентные мастерские операции:
   - `PUT /api/clients/:id/block`;
   - `DELETE /api/clients/:id/block`.
4. Проверять роль мастера и принадлежность `MasterClient` текущему мастеру.
5. Для ручного клиента без MAX-аккаунта блокировка недоступна.
6. Выполнять block/unblock под тем же advisory lock мастера, что и создание записи.

## Кабинет мастера

Экран: `master-app/src/pages/ClientsPage.tsx`.

1. В обычном состоянии добавить нижнюю кнопку `Заблокировать`.
2. Показывать подтверждение:
   - заголовок `Заблокировать клиента`;
   - текст `Клиент не сможет записываться на услуги и не будет получать уведомления`;
   - красная кнопка подтверждения и кнопка `Отмена`.
3. После ответа API синхронно обновлять выбранного клиента и строку в списке.
4. В заблокированном состоянии скрыть действия записи/сообщения и показать:
   - точную иконку из `~/Downloads/forbidden.svg` размером 32x32;
   - заголовок `Клиент заблокирован`;
   - пояснение из макета;
   - нижнюю кнопку `Разблокировать`.
5. Для разблокировки использовать модалку из четвёртого макета с primary-кнопкой.

Существующий `ConfirmDialog` уже содержит размеры макета: внешние padding
`20px 16px 24px`, кнопки высотой 44px и radius 22px, gap между кнопками 8px.
Типографика берётся из `text.h4`, `text.body2`, `text.callout1`; цвета только из
семантических CSS-токенов.

## Клиентский miniapp и бот

1. Добавить авторизованный `POST /api/masters/:id/client-access`.
2. Не фильтровать `GET /api/masters/recent` и не скрывать мастера из списка.
3. Проверять доступ перед загрузкой профиля мастера.
4. При блокировке отправлять клиентским ботом сообщение:

   ```text
   ❌ Мастер не доступен

   К сожалению, доступ к профилю мастера, а также запись на его услуги больше не доступны
   ```

5. Добавить кнопку `Другие мастера` со ссылкой
   `https://max.ru/<client-bot>?startapp=cmasters`.
6. Закрывать miniapp через `window.WebApp.close()` только после подтверждённой
   отправки сообщения MAX API. При ошибке доставки оставлять безопасный экран.
7. Защитить отправку короткой Redis-дедупликацией от повторов.

`startapp=cmasters` уже ведёт на `/masters`, поэтому отдельный клиентский маршрут
не нужен.

## Серверные ограничения

Проверять блокировку внутри транзакции после advisory lock для:

- обычной клиентской записи;
- клиентской пакетной записи;
- переноса записи клиентом;
- финального подтверждения записи в клиентском боте.

Стабильная ошибка: `403 CLIENT_BLOCKED_BY_MASTER`. Отмена существующей записи
остаётся доступной.

Перед каждой отправкой клиентского уведомления проверять пару
`masterId + clientId`. Мастерские уведомления не блокируются.

## Проверки

1. Блокировка и разблокировка из карточки клиента, cancel и защита от double click.
2. Изоляция блокировки между разными мастерами и клиентами.
3. Запрет regular/package/reschedule для клиента и разрешение записи мастером.
4. Подавление всех клиентских уведомлений заблокированной пары.
5. Мастер остаётся в списке последних мастеров.
6. Открытие по UUID и из списка отправляет одно сообщение и закрывает miniapp.
7. Кнопка `Другие мастера` открывает `startapp=cmasters`.
8. Ошибка MAX API не закрывает miniapp.
